# 变化类型 → 模式 选型表（L3）

用法：先通过 `cards/C08` 的入口确认"变化点 + 时间窗"，再查本表。**本表只提供候选，不提供许可**——找不到"不适用条件"被排除的理由，才可选。

## 书内详述的四个模式（9.5）

| 变化类型 | 候选模式 | 不适用条件（命中即放弃） |
|---|---|---|
| 对象的创建过程复杂/重复，且需要按原型复制新对象 | **Prototype** | 对象创建只有一种方式且无复制需求；对象持有大量外部资源无法浅拷贝 |
| 需要给对象**动态、可组合**地增加职责，且子类组合会爆炸 | **Decorator** | 职责组合是固定的（用继承即可）；只有 1–2 种组合 |
| 要为复杂子系统提供**一个简单入口**，且大多数调用方只需要默认视图 | **Facade** | 子系统本身简单；调用方需要精细控制每个子模块 |
| 一方状态变化要通知多方，且发布方**不需要知道具体订阅者** | **Observer** | 只有 1 个固定接收方（直接调用即可）；通知需要强一致/事务性 |

## 通用补充（非书内详述，仅作候选池）

| 变化类型 | 候选模式 | 不适用条件 |
|---|---|---|
| 算法/规则可在运行期替换，且分支按类型分叉 | Strategy | 分支数固定且 ≤2；分支不含行为差异只含数据差异 |
| 产品族需要成套创建、且族内实现必须配套 | Abstract Factory | 只有一个产品族；族内对象没有配套约束 |
| 构建过程步骤固定、表示可变 | Builder | 对象构造只有 2–3 个参数 |
| 需要把接口转换成调用方期望的形态（多为外部耦合） | Adapter | 能直接改接口定义 |
| 跨对象的请求链需要解耦（谁处理不确定） | Chain of Responsibility | 处理者固定且顺序确定 |

## 选型后必须补的一行

```markdown
依据: 变化点=<什么会变> | 时间窗=<半年/1年/2年/3年> | 模式=<X> | 不适用条件已排除=<理由>
```

缺任何一项 → 回到 `cards/C08` 第 1 步，不要进入实现。

## 三个常见误配

| 现象 | 真相 | 处置 |
|---|---|---|
| 只有一个实现就先抽接口 + 工厂 | 过度设计（NOP） | 等第二个实现出现 |
| 用 Facade 包住一个上帝类 | 职责没分，只是遮住 | 回去做 C05 |
| 用 Observer 传递需要事务一致的状态 | 模式不解决一致性问题 | 改同步调用 + 事务边界 |

> 出处：9.2（模式只是一把锤子）、9.3（找到变化/封装变化）、9.4（原则 vs 模式）、9.5（四模式详解）
