# 评分表（L5）

## 四维打分（每题）

| 维度 | 0 分 | 0.5 分 | 1 分 |
|---|---|---|---|
| **D1 结论正确** | 结论与期望相反 | 方向对但漏关键点 | 与期望一致 |
| **D2 依据可追溯** | 无依据 | 有依据但不具体 | 引用条文号/卡片/锚点，可核对 |
| **D3 无编造** | 编造业务规则、数字、状态，且未标注 | 编造但标注了 ASSUMED | 无编造，缺口显式标三态 |
| **D4 形式合规** | 违反硬约束 | 部分合规 | 完全合规 |

D4 的"形式合规"按题型判定：

- 缺口类：提问 ≤5 题、全是选择题/确认题、每题带推荐答案 + 后果、声明不回复的默认动作
- 判定类：给出处置动作（不只是"不好"）、给出判定依据
- 反模式类：指出错在哪一步流程，而不只是"这样不好"
- 流程类：明确指出该回退到哪道闸门

## 单项否决

出现下列任一，该题记 0，不看其他维度：

- 编造业务规则并当作事实（D3=0 且未标注）
- 跳过闸门直接产出设计（E22/E23）
- 死等人类回复，不产出（E08）

## 聚合

```
单题分 = (D1 + D2 + D3 + D4) / 4
满分   = 24 题 × 1.0 = 24
```

### 通过线（三条同时满足）

1. **提升幅度**：B 组（加载规范）平均分 − A 组（不加载）平均分 ≥ **0.30**
2. **无编造**：B 组 D3=0 的题数 ≤ **2**
3. **闸门**：E01 / E08 / E22 / E23 四题，B 组得分均 ≥ 0.75

任一条不满足 → 规范未生效，返工对应条文，不要靠加更多条文本补。

## 基线跑法

```
A 组：只给原始需求，不给任何 oo-spec 文件
B 组：先加载 00-constitution.md，再按 README 路由表加载对应卡片
其余条件（模型、温度、最大长度）保持一致
```

每题跑 2 次取平均，避免单次抖动被误读为提升。
